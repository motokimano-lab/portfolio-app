# 投資信託の実口数管理

Positionsに新列がなければ従来方式を維持する。Google Sheetsの移行は別作業。
実口数方式では `instrument_type=mutual_fund`、`fund_code`、`product_name`、
`price_unit=10000`、`currency=JPY` を使用する。tickerは `MF:<fund_code>`。
quantityは実口数、cost_priceは1万口あたりの平均取得価額。
ファンドコードは文字列として読み込み、先頭の0を保持する。

評価額は `quantity / price_unit * price * fx_to_jpy`。
取得額も同様。円建て投信の為替倍率は1。
eMAXIS SlimとSBI・Vはdisplay_nameをSP500、楽天SCHDはSCHDにする。
口座種別はNISA／旧NISA／Jr.NISA／特定を別々に保持する。
現行PositionsのNISAから旧NISAやJr.NISAを推測しない。
移行時は読み取り済みの「投信→ETF」など、実際の口座区分を確認した資料を使う。

## 公式データと分配金

- 楽天SCHD 9I312249: 楽天投信の最新NAV、履歴CSV、分配履歴CSV。
- eMAXIS Slim 03311187: MUFG公開APIと履歴CSV。
- SBI・V 89311199: SBI公式サイト案内先の履歴CSVと分配履歴XML。

TTMは日本時間の当日から過去365日、開始日を含まず当日を含む公式分配額の合計。
年間推計は最新決算の分配額×決算回数（楽天4、他2本1）。
どちらも現在口数÷10000を掛けた年間インカム力で、実際の入金額ではない。
分配0円は公式履歴から取得し、将来の分配は自動反映する。
取得失敗時にはETFへ代替せず、画面集計とログ保存を停止する。
基準日が当日以前なら休業日・公表前を含む未更新警告を表示する。
SBIのXMLとNAVの更新日差も警告する。

## 税引後参考額

楽天SCHDは全額普通分配、外国税10%、外国税相当額満額控除の標準モデル。
公式分配額Dに対し、グロスアップG=D/(1-外国税率)。
所得税=max(0,G×所得税率-G×外国税率)、住民税=G×住民税率。
参考額=D-所得税-住民税。税率0.15315、0.05、0.10から約88.5389%を算出する。
NISA・旧NISA・Jr.NISAの投信はDをそのまま使い、外国税を再控除しない。
他の投信は商品属性によって処理し、海外株・ETFは従来の外国税控除を維持する。
移行前のVOO/SCHD proxy行の計算は従来どおり。
普通／特別分配や通知外国税相当額の個別再現は行わない。実入金は家計簿で管理する。

モデルの根拠: https://www.rakuten-sec.co.jp/web/rfund/guide/tax2.html

## Daily_Log移行

6列の記録形式と当日分置換を維持し、過去ログを書き換えない。
同じdisplay_nameのVOO/SCHDからMF:への切替を日次ログから検出する。
移行をまたぐ比較では対象銘柄の騰落率を欠損値にし、ランキングから除外する。
全体・資産分類・セクターの金額差は記録額の差を保持するため移行差を含む。
画面と既存通知の文章にその旨を示す。移行後のみの期間では通常比較に戻る。
6列にはowner/account_typeがないため、検出はdisplay_name単位で行う。
同じ名前の一部を移行した場合もその名前全体をランキングから除外する。

## 確認方法

`python -B -m unittest discover -s tests -v`

テストは固定公式データ、税モデル、非課税区分、旧評価額の不変性、将来分配、
取得失敗、移行検出、6列の保存と当日置換を検証する。
save_log.pyをそのまま実行すると既存の保存・Discord通知が行われるため、
読み取り確認では保存の直前までを実行するか、外部処理を模擬実装に置き換える。
